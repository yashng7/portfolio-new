System Summary

OpenKeyboard is a browser-native WebHID control panel for supported mechanical and Hall-effect (magnetic) gaming keyboards. It tunes per-key actuation (0.1mm–4.0mm), Rapid Trigger, SOCD / Snap Tap, multi-layer keymaps, per-key RGB, macros, and smart profiles—without installing vendor bloatware.

Architectural Overview

Inspired by the OpenMouse-Project, OpenKeyboard replaces heavyweight desktop configuration suites with a single web app built on the WebHID API. It pairs a live hardware connection layer with a fully interactive virtual simulator, separating staging from writing so profiles can be edited and persisted locally before ever touching the board.

Core Subsystems & Capabilities

01 // WebHID Engine & Virtual Hardware Simulator

  • Native WebHID Connectivity: Connects supported USB and 2.4GHz boards via navigator.hid across Wooting, Keychron HE/QMK, Wuque Studio, NuPhy, MonsGeek/Akko, DrunkDeer, Razer, and generic VIA/QMK devices.
  • Virtual Hardware Simulator: Five switchable simulated boards with a live 32-byte HID frame inspector for developing and demoing without physical hardware.
  • Physical Device Grouping: Groups the per-interface HIDDevice objects Chrome exposes into logical keyboards and targets only the vendor / VIA raw-HID collection.
  • VIA Handshake Probing: Confirms a board is present via id_get_protocol_version, reading back protocol, firmware, and layer count.

02 // Visual Keymap & Multi-Layer Remapper

  • Physical Geometry Switchers: Layouts for 60%, 65%, 75%, TKL (80%), and Full-Size (100%).
  • Four Hardware Layers: Base plus Fn1/Fn2/Fn3 layer editing with Hyper/Meh/Mod-Tap keys.
  • Live Key Capture: Real-time physical key-press capture for fast binding reassignment.

03 // Magnetic Tuning & SOCD (Snap Tap)

  • Per-Key Actuation: Continuous actuation point adjustment from 0.10mm to 4.00mm.
  • Rapid Trigger Controls: Press/release sensitivity (0.05mm–2.00mm), Continuous Rapid Trigger, and Top/Bottom deadzones.
  • SOCD / Snap Tap Manager: Counter-strafe pair configuration with a live A+D tester and real-time ADC Stem Travel Gauge.

04 // RGB Lighting Studio & Macro / Diagnostics Suite

  • Lighting Studio: Nine matrix effects, PWM brightness/speed controls, chassis underglow sync, and an interactive per-key RGB brush painter.
  • Macro Studio: Eight on-board macro slots (M1–M8) with a live keystroke timestamp recorder.
  • Hardware Diagnostics: NKRO Rollover Matrix tester and Switch Chatter / Double-Bounce Analyzer with ms delta tracking.
  • Switch Acoustics Synthesizer: Web Audio API sound modelling for Lekker HE, Gateron Oil King Thock, Holy Panda, and Box Jade Clicky profiles.

05 // Smart Profile Advisor

  • Server-Side Advisor API: A Next.js route (/api/jev-advisor) auto-calibrates actuation, Rapid Trigger, SOCD, and polling rate for any game or workflow.

Technical Specification

  • Framework: Next.js App Router with strict TypeScript end-to-end.
  • Hardware Protocol: VIA raw-HID over WebHID — 32-byte reports via sendReport(0, …) with command echo in byte 0.
  • State & Persistence: Workspace staging mirrored to localStorage; explicit "Write to Board" gated behind a successful VIA handshake.
  • Design System: OpenMouse Material Design 3 (M3) five-theme token system — Dark, Light, Ocean, NieR, and Catppuccin.
  • Deployment: Vercel-hosted Next.js with a serverless advisor API route.

Engineering Challenges & Solutions

Honest Hardware Writes with Unreliable Device Metadata: WebHID exposes no "enumerate all devices" API, and VIA keycode writes require matrix row/column coordinates from a board definition that is no longer publicly hosted. Rather than guess and risk remapping the wrong physical key, OpenKeyboard stages edits safely, verifies writes with a read-back, and reports boards exposing no vendor interface as read-only instead of pretending settings were applied. When no writable board is connected the action reads Save to Browser, and the app never claims a hardware write.
